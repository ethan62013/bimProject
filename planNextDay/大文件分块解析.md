# 大文件：先分块解析，再查看

## 目标

选中 IFC 之后先分块解析，解析器关闭后再进入场景。查看阶段不再调用 `OpenModel`，也不再常驻 `IfcAPI`。

第一版解决「解析和全部网格叠在同一块 wasm 内存里」的崩溃。相机按距离装卸块放到下一版。`OpenModel` 自身就超过 3GB 的文件，浏览器里无法切开，仍会失败，留给以后的 IfcOpenShell 转换器。

小于 32MB 的文件保持 `src/main.js` 里现在的路径：`openBuffer` → `loadIfc` → `viewer.setModel`。

## 现状

- `src/loader.js` 的 `WASM_MEMORY_LIMIT` 是 3GB。`loadIfc` 在同一次调用里完成 `OpenModel`、`buildTree`、`buildMeshes`，并一直留着 `api` 和 `modelID`。
- `OpenModel` 使用 `COORDINATE_TO_ORIGIN`、按文件大小递减的 `CIRCLE_SEGMENTS`，以及 3GB 的 `MEMORY_LIMIT`。
- `buildMeshes` 用 `StreamMeshes` 分批取网格，重文件每 40 个构件刷新一次，但 `flushChunks` 之后全部 `BatchedMesh` 都留在 `model.group`。
- 曲面三角化失败时，`hookGeometryLogs` 收集 `No basis found for brep` / `TriangulateBounds`，`abortMessage` 把 wasm 中止区分成「面片无法三角化」和「可能超出内存上限」。
- `src/main.js` 的 `openBuffer` 解析完立刻 `viewer.setModel`。属性由 `beginPropertyIndex` 在仍然打开的模型上建 `defs` 和 `text` 两个 `Map`。
- `readElementProperties` 通过 `GetRawLineData` 读属性。
- 目录树、隔离、楼层、隐藏都依赖 `expressID`。剖切用材质上的 `clippingPlanes`，测量和点选对着场景里的网格。

解析和查看占的是同一块内存。分块的意义是每写完一块就丢掉几何，最后关掉 Worker，查看时只读已经写好的块。

## 使用流程

1. 用户选择文件。32MB 以下走现有 `loadIfc`。
2. 更大的文件用「文件名 + 字节大小 + 修改时间」查 IndexedDB。命中则跳过解析。
3. 未命中时，状态栏显示分块进度，场景保持空白。
4. Worker 解析并写出模型包。每写完一块就从 Worker 内存丢掉。
5. `CloseModel` 后终止 Worker。3GB 的 wasm 内存到这里释放。
6. 主线程读取模型包，调用 `viewer.setModel`。目录树来自包里的 `tree`。
7. 点选构件时再读取对应的属性分片。同一文件下次用缓存，跳过解析。

## 模型包

IndexedDB 数据库名 `ifc-view`，一个模型一个 object store，键是缓存键。

记录：

- `manifest`：版本、包围盒、已减去的中心、`unitScale`、块列表。每块有 `id`、楼层名、是否空间、三角面数、字节数、包围盒、包含的 `expressID`。
- `expressIndex`：`expressID` 到块 id 列表。隔离、按楼层显示、按材质隐藏用它找块。
- `tree`：`buildTree` 的结果，含每个节点的 `expressIDs`。
- `tile:<id>`：一块几何的二进制。
- `props:<shard>`：约 2000 个构件的属性 JSON。

几何在写出前完成两件事：乘上 `readLengthScale` 得到的米制比例，再减去整体中心。查看器不再对 `group` 做 `scale` 和二次平移。

一块的目标是 15 万到 30 万三角面，或 4MB 到 8MB。先按 `IfcBuildingStorey` 分组，再按平面网格切开。`IfcSpace` 单独成块，并在 manifest 里标为空间，对应现在的空间按钮，默认不加载。`hiddenExpressIds` 的构件不写入块。无法三角化的曲面沿用现在的跳过统计，记进 manifest，不让整次解析中止。

块内按材质键分组，字段与现在的 `takeChunk` 一致：材质键、`Float32` 位置、法线、索引，以及 `{ expressID, indexStart, indexCount }`。写细块时每 16 个三角形抽一份，汇总成该楼层的粗块。打开时先显示粗块。

## 代码落点

新增三个文件：

- `src/package-format.js`：块的二进制读写、manifest 结构。
- `src/compile-worker.js`：只负责 `web-ifc` 解析。从 `loader.js` 移入 `OpenModel`、`buildTree`、`StreamMeshes`、材质键、属性读取。几何通过 `postMessage` 转移给主线程，不在 Worker 里攒完整模型。
- `src/model-store.js`：IndexedDB 读写。

主线程改动：

- `src/main.js` 的 `openBuffer` 增加分支。大文件调用 `compileIfc`，完成后再 `loadPackage`。进度文案继续走现有的 `setStatus`。
- `src/loader.js` 增加 `loadPackage(manifest, tiles)`。它把块恢复成 `BatchedMesh`，返回的 `model` 形状保持 `{ group, byId, ids, batches }`。`session.api` 为空。`closeModel` 在没有 `api` 时只释放网格。
- `readElementProperties` 在没有 `api` 时从属性分片读取，返回值仍是现在的分组结构，供点选面板和目录搜索使用。
- `viewer.js` 第一版不改交互。`setModel` 仍接收一个已经装好块的 `group`。粗块先加入，细块在同一次加载里跟着加入。

## 实现顺序

1. 定二进制格式，并用一个小 IFC 从现有 `buildMeshes` 结果写出再读回。画面、点选 ID、剖切应与直接打开一致。
2. 把解析挪进 Worker。主线程只收块并写入 IndexedDB。完成后终止 Worker，确认这块 wasm 内存释放。
3. `openBuffer` 接上缓存判断和进度文案。第二次打开同一文件不再出现「正在解析 IFC」。
4. 属性改读分片。点选和目录搜索不再调用 `GetRawLineData`。
5. 用一个会在当前路径里因内存失败的大文件验收。解析过程中场景为空，完成后能旋转、点选、测量、剖切。

## 验收

- 32MB 以下的文件仍是一次打开，不写 IndexedDB。
- 大文件第一次有分块进度，第二次直接进入场景。
- 进入场景后不再存在活动的 `web-ifc` 实例。
- 点选构件能看到类型、名称和属性集。
- 楼层隔离、构件隔离、空间开关仍按 `expressID` 工作。
- 单个面片无法三角化时跳过并计数，不把整次分块解析判成内存失败。
- 超过 `OpenModel` 3GB 上限的文件仍提示无法在浏览器里解析，不进入半成品场景。

## 这一版先不做

- 查看时按相机视锥装卸细块，以及大约 800MB 的驻留上限。第一版进入场景后可以一次读入全部细块。解析器的 3GB 限制先解开；特别大的模型如果在显卡或 JavaScript 堆上撑满，再做装卸。
- IfcOpenShell 命令行转换器。它和浏览器包使用同一种格式，用来处理 `OpenModel` 直接失败的文件。
